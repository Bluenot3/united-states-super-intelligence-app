# USSI ecosystem and publishing boundaries

USSI is the public discovery, visual theme preview, and outcomes exploration surface for the ZEN ecosystem. Arsenal remains the protected operating environment. This implementation does not introduce a second authentication system, program runtime, credit ledger, entitlement service, model router, or artifact store.

## Dataset boundaries

The supplied `AI Pioneer Outcomes Explorer (1).html` contains 34,300 synthetic records: 6,200 for 2024, 11,300 for 2025, and 16,800 for 2026. It identifies generation as NumPy PCG64 with seed `20270101`. Every learner, site, app, score, deployment, and telemetry figure in that dataset is modeled. The UI must not frame these as observed enrollment or program impact.

- Deployment rate: stage S2 or above divided by the current filtered learner population.
- Public launch rate: stage S5 or above divided by that population.
- Capstone rate: stage S7 divided by that population.
- 90-day survival: deployed records marked live at 90 days divided by deployed records.
- Score gain: mean post-score minus pre-score in the current population, with fixed-point scaling respected.
- Time to first deployment: median modeled days among deployed records.
- App users: sum of users on deployed apps; no cross-app person deduplication.

The source marks 2027 and 2026 retention into 2027 as sealed until March 30, 2027. USSI must not fabricate missing cohort records, infer retention, or promise that a timer will fetch unpublished data. Future release requires an explicitly reviewed dataset.

There is no counterfactual comparison group. Cohort improvement, equity differences, hosting reliability, and user-count distributions reflect model assumptions, not causal findings. Source-site codes must not be mapped to actual youth organizations or locations.

## Future Arsenal admin publication contract

An admin connector is a future integration, not an active feature in this preview. Arsenal should authenticate the administrator, validate permission server-side, and publish a deliberately approved aggregate payload to USSI. USSI should consume published read-only summaries.

Each public metric should include its stable metric ID, value, unit, reporting period, population, numerator/denominator or aggregation definition, source provenance, synthetic/observed status, publication timestamp, and review state. Distinguish a reporting period from the time the dashboard was refreshed. Use revision history and explicit corrections so a later update does not silently rewrite an earlier public claim.

Publish aggregate summaries only. Private learner records, course answers, completion controls, credentials, patient or client information, operator secrets, credit balances, service-role credentials, and provider tokens do not belong in a public bundle or browser connector. Any real student-data publication requires a separate governance and consent process in its existing source systems.

## Change scope

The USSI preview extends a new public site. It does not modify Arsenal, ZEN AI World, wallet source repositories, DNS, production hosting, live account behavior, Stripe, Supabase, or course infrastructure. Visual exploration should remain reversible while deployment and any connector are reviewed separately.
